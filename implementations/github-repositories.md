# GitHub Repositories and Implementations

## Topic

**The Influence of Citation Formatting on Human Trust in Fabricated Resources**

This collection contains open-source GitHub implementations relevant to citation verification, citation hallucination detection, bibliographic validation, and hallucination evaluation in AI-generated content.

> **Selection note:** These projects were selected because their functionality is directly related to detecting fabricated references, validating citation metadata, or evaluating hallucinations in language-model outputs. The links point to the repositories so that users can inspect the source code, documentation, license, and implementation details.

## 1. RefChecker

**Repository:** https://github.com/amazon-science/RefChecker

**Purpose:** RefChecker is a framework and benchmark for detecting fine-grained hallucinations in large language-model outputs.

**Key implementation features:**
- Breaks generated responses into knowledge triplets.
- Checks claims at a fine-grained level.
- Provides an automatic hallucination-checking pipeline.
- Includes a benchmark for evaluating hallucination detection.
- Supports evaluation of different LLM settings.

**Relevance to this project:** Citation integrity is closely connected to whether claims in AI-generated research are supported by reliable evidence. RefChecker provides an implementation approach for checking generated claims rather than trusting fluent output.

**Repository license/documentation:** See the GitHub repository for the current license and setup instructions.

## 2. HALLMARK

**Repository:** https://github.com/rpatrik96/hallmark

**Purpose:** HALLMARK is a benchmark for evaluating tools that detect hallucinated citations in academic papers.

**Key implementation features:**
- Citation-hallucination benchmark
- Multiple hallucination types
- Different difficulty tiers
- DOI resolution checks
- Title and author consistency checks
- Venue verification
- Cross-database agreement
- Multiple baseline verification tools
- Evaluation metrics such as F1 and detection rate

**Relevance to this project:** This is directly aligned with the project's citation-integrity objective. It provides a structured way to evaluate how well citation-verification tools distinguish genuine and hallucinated references.

**Repository license:** MIT License, as listed by the repository.

## 3. BibTeX Verifier

**Repository:** https://github.com/stvsun/bibtex-verifier

**Purpose:** BibTeX Verifier checks BibTeX references against Crossref and Semantic Scholar to identify potentially fabricated or hallucinated bibliography entries.

**Key implementation features:**
- Reads BibTeX files.
- Searches Crossref and Semantic Scholar.
- Compares titles, authors, years, and venues.
- Produces verification classifications.
- Generates machine-readable and human-readable reports.
- Supports cached verification results.

**Relevance to this project:** This implementation closely matches the citation-audit process used in the research project. It can automatically flag suspicious references that need manual verification.

**Important limitation:** A repository match does not automatically prove that every citation is correct. The project's documentation recommends manually reviewing suspicious results and checking metadata.

## 4. CheckIfExist / References-Validation

**Repository:** https://github.com/zabbonat/References-Validation

**Purpose:** CheckIfExist is an open-source reference-verification tool designed to detect citation hallucinations and validate bibliographic references.

**Key implementation features:**
- Cross-checks references against Crossref.
- Uses Semantic Scholar and OpenAlex.
- Supports additional scholarly sources such as DBLP and arXiv.
- Checks citation metadata.
- Flags potentially fake authors, mismatched years, and other inconsistencies.
- Provides a web-based interface and local execution option.

**Relevance to this project:** The tool directly addresses the central problem of fabricated scholarly references generated by AI.

**Associated research:** Abbonato's 2026 work describes CheckIfExist as a multi-source bibliographic validation system.

---

## 5. CiteTracer

**Repository:** https://github.com/aaFrostnova/CiteTracer

**Purpose:** CiteTracer is a multi-agent framework for detecting citation hallucinations using structured field-level verification.

**Key implementation features:**
- Extracts citations from PDFs and BibTeX.
- Retrieves supporting bibliographic evidence.
- Uses deterministic field matching.
- Handles ambiguous cases through specialized verification steps.
- Uses a taxonomy covering real, potentially problematic, and hallucinated citations.
- Provides a benchmark for citation-hallucination detection.

**Relevance to this project:** CiteTracer is particularly relevant to the project's goal of distinguishing genuinely supported citations from references that only appear credible.

## How These Implementations Support the Project

The five implementations represent different levels of verification:

1. **RefChecker** focuses on whether generated claims are supported.
2. **HALLMARK** evaluates citation-hallucination detection systems.
3. **BibTeX Verifier** checks bibliographic records against scholarly databases.
4. **CheckIfExist** validates references across multiple scholarly sources.
5. **CiteTracer** performs structured, field-level citation verification.

Together, they demonstrate that citation trust can be studied computationally by checking whether a cited work exists, whether its metadata matches, and whether generated claims are actually supported by evidence.

## Recommended Use in This Project

For a small manual citation audit, use the following workflow:

1. Extract each reference from the research paper.
2. Search the exact title in a scholarly database.
3. Check author names, publication year, venue, and DOI.
4. Resolve the DOI or publisher record where available.
5. Compare the citation with the authoritative metadata.
6. Check whether the source actually supports the claim.
7. Record the final classification in the citation-integrity audit.
8. Use automated GitHub tools as supporting evidence rather than treating their verdicts as infallible.

## Important Limitations

Automated citation-verification tools can produce false positives or false negatives. A reference that cannot be found in one database is not automatically fabricated, because indexing coverage varies. Likewise, finding a real paper does not prove that the citation's metadata is completely correct or that the source supports the claim.

For academic use, suspicious results should be manually checked against authoritative publisher, DOI, journal, or scholarly records.
